## 1. Архитектура интерфейса

**Стек.** TanStack Start (React 19, файловые маршруты), Tailwind CSS v4 (`@import "tailwindcss"` в `src/styles.css`), примитивы shadcn/ui стиля new-york на Radix, иконки lucide, анимации `motion` v13 (`motion/react`) и `tw-animate-css`, уведомления `sonner`, данные через React Query и серверные функции `createServerFn`, Supabase (Lovable Cloud).

**Маршруты** (`src/routes`):

| URL | Файл | Назначение |
| --- | --- | --- |
| `/` | `index.tsx` (1136 строк) | Auth gate + вся оболочка приложения + Обзор, Профиль, Уведомления/заявки |
| `/auth` | `auth.tsx` | Вход |
| `/change-password` | `change-password.tsx` | Обязательная смена временного пароля при первом входе |
| `/owner-reset` | `owner-reset.tsx` | Служебная установка пароля владельца |
| 404 / ошибка | `__root.tsx` | `NotFoundComponent`, `ErrorComponent` |

**Навигация** — не маршруты, а состояние `active: ScreenId` в `index.tsx:162`. Семь вкладок (`index.tsx:139-147`): Обзор, Сотрудники, Задачи, База знаний, Уведомления, Настройки, Профиль. Дополнительно в шапке: кнопка «Админ» (`adminOpen`, видна при `admin.access`), основная кнопка «+ Заявка» (диалог: задача или запрос доступа) и аватар, открывающий Профиль. Вкладки не имеют URL: нет глубоких ссылок и кнопки «назад». Это ограничение фиксируется, но маршруты в рамках редизайна не меняются.

**Ленивые чанки:** AdminPanel, EmployeeDirectory, KnowledgeBase, SettingsPanel, TaskWorkspace (префетч при наведении на вкладку «Задачи», `index.tsx:22-31`).

**Глобальные стили и токены** (`src/styles.css`):
- токены shadcn в OKLCH (`:root`, строки 51-85); блок `.dark` (87-120) полностью дублирует `:root`. Приложение **только тёмное**, класс `dark` вешается вручную на корневой `div` каждой страницы;
- `--radius: 0.625rem` (10 px), производные `--radius-sm…4xl`;
- нейтральные цвета тёплые, с коричневым оттенком (hue 60): фон `#0E0C0A`, карточка `#171412`, secondary `#221E1C`. Акцент `--primary` `oklch(0.72 0.17 55)` ≈ `#F3821D`;
- `AmbientFlowBackground` (строки 134-225 и `.tsx`) — фон всего приложения: canvas с «лентами», 20 fps, пониженное разрешение, пауза при скролле и скрытой вкладке, затемнение при открытом диалоге и фокусе в форме. Его база **холодная, сине-серая** (`oklch(0.135 0.008 255)`): под тёплыми карточками лежит холодный фон;
- `AuthBackground` (247-353) — отдельный CSS-фон экрана входа: тёплые пятна, зерно, 6 частиц;
- настройки интерфейса: `html[data-density="compact"] main` уменьшает `--spacing`, а `html[data-motion="off"]` обнуляет все CSS-анимации (231-245).

**Шрифты.** Собственных шрифтов нет. Используется системный стек Tailwind v4: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto…`. На macOS это SF Pro, на Windows — Segoe UI **[браузер: computed `font-family`]**. Для номеров, кодов и таймеров — `font-mono`.

**Анимации:**
- `motion/react` используется в `TaskWorkspace` (пресеты `EASE_OUT` 0.24 с и `SOFT_SPRING`, `layoutId` для выделения и фильтра, `AnimatePresence`), `SettingsPanel` (переключатель), `ProfileAvatar`, `profile-display` (`VipBadge`);
- Radix-диалоги анимируются через `tw-animate-css`;
- `MotionConfig reducedMotion="user"` задан только в `TaskWorkspace` и `ProfileAvatar`;
- переключатель «Анимации» в Настройках выставляет `MotionGlobalConfig.skipAnimations` и `data-motion` (`src/lib/ui-preferences.ts`).

**Состояния:**
- загрузка — в основном текст «Загрузка…». Скелетоны есть только у вкладки «Задачи» (`TasksSkeleton`) и у KPI;
- ошибки — по-разному: красный текст, приглушённый текст, `role="alert"`-плашки, тосты;
- пустые состояния — продуманные, по схеме «иконка + заголовок + пояснение».

**Связь визуального слоя с логикой.** Визуальная разметка и логика в большинстве экранов **в одних файлах**:
- `index.tsx` содержит auth gate (строки 194-417), шапку, Обзор, Профиль, заявки;
- `TaskWorkspace.tsx` (1412 строк) — мемоизированные строки, кастомный компаратор `sameTaskDetailInputs`, изолированный тикер `LiveSpent`.

Поэтому редизайн выполняется правкой классов и разметки внутри существующих компонентов, без переноса логики.

**Неиспользуемые примитивы:** `ui/select`, `ui/switch`, `ui/checkbox`, `ui/skeleton`, `ui/sidebar`, `ui/sheet` и другие лежат в репозитории, но в экранах не используются. Вместо них — нативные `<select>` (13 шт.), нативные чекбоксы (4) и собственный `Switch`.

## 3. Аудит экрана авторизации

**Реализация** (`src/routes/auth.tsx`):
- состояние `email`, `password`, `busy`;
- `supabase.auth.signInWithPassword({ email, password })`, при успехе — `navigate({ to: "/" })`;
- при ошибке — `toast.error` с текстом ошибки и техническими `code: … · status: …`;
- кнопка блокируется на время запроса. При заблокированной submit-кнопке неявная отправка по Enter тоже не срабатывает, поэтому защита от повторной отправки есть;
- валидация только HTML: `required`, `type="email"`, `minLength={6}` у пароля. 6, а не 12, оставлено намеренно: старые пароли могут быть короче новой политики;
- дальнейший маршрут решает auth gate на `/`: проверка состояния учётных данных (→ `/change-password` или «пароль истёк») → загрузка профиля (→ «Доступ закрыт» при ошибке) → рабочее пространство, присутствие, проверка `admin.access`.

**Что видно на экране [браузер]:**
- карточка шириной 384 px по центру поверх `AuthBackground`;
- логотип PNG высотой 64 px, подпись «Вход в рабочее пространство»;
- поля «Email» и «Пароль», оранжевая кнопка «Войти»;
- сноска «Учётные записи выдаёт владелец LUNO DIGITAL».

**Проблемы:**
1. **Типовая «форма в карточке»**, ровно то, чего бриф просит избегать. Нет композиции, заголовка и ощущения продукта: карточка висит в пустоте.
2. **Логотип теряется.** Слово «LUNO» в PNG — тёмно-графитовое и на тёмной карточке почти сливается; читается только оранжевая часть [браузер]. Комментарий в `BrandLogo.tsx` запрещает изменять оригинал, поэтому нужна светлая или монохромная версия логотипа от владельца бренда. Та же проблема в шапке приложения (34 px).
3. **Ошибки показываются только тостом** в правом верхнем углу, далеко от формы. В тексте — технические `code`/`status`. Нет ошибки у поля, рядом с формой нет `aria-live`.
4. **Нет `autoComplete`** (`username`, `current-password`): менеджеры паролей работают хуже.
5. **Нет переключателя видимости пароля** (его нет и сейчас; добавление — только по согласованию, см. раздел 10).
6. **Состояние загрузки** — только смена текста «Подождите…», без индикатора. Ширина кнопки стабильна, это хорошо.
7. **Фокус-кольцо** 1 px, оранжевое; на тёмном фоне едва заметно [браузер].
8. **Смесь языков:** подпись «Email» по-английски, `html lang="en"` (`__root.tsx:112`) при русском интерфейсе. Страдают переносы, экранные чтецы и проверка орфографии.
9. **Мобильная ширина 375 px:** карточка помещается, но сноска переносится с висящим словом «DIGITAL» [браузер].
10. **Переход после входа:** между формой и рабочим пространством — голый текст «Проверяем сессию…» на чёрном фоне (`index.tsx:419-425`), без логотипа и фона. Первое впечатление обрывается.
11. **`/change-password` — часть первого входа** каждого нового сотрудника, но выглядит иначе: нет фона, логотипа и общей композиции (`change-password.tsx:112-118`). `/owner-reset` — технический английский заголовок «TEMPORARY OWNER PASSWORD SETUP».
12. **Нефункциональные замечания** (не трогаются без отдельного решения):
    - в продакшене пишутся `console.info("AUTH DEBUG …")` (`auth.tsx:33-69`);
    - текст «Сервер авторизации не ответил за 20 секунд» (`auth.tsx:60`) не соответствует настройкам: 20-секундного таймаута в клиенте нет. В `client.ts` его нет, в `previewAuthStorage.ts` — только 2-секундный таймаут хранилища.

**Сильные стороны:**
- спокойный тёплый фон без canvas;
- `prefers-reduced-motion` и переключатель анимаций соблюдаются;
- кнопка на всю ширину;
- блокировка повторной отправки;
- честная сноска о выдаче учётных записей.

## 4. Визуальные проблемы по экранам

### 4.1 Общие для всего приложения
- **Анимация смены вкладок не работает.** Класс `animate-fade-in` используется в 8 местах (`index.tsx:754,1034,1067`, `EmployeeDirectory.tsx:188`, `KnowledgeBase.tsx:55,220,363`, `SettingsPanel.tsx:157`), но не определён ни в `styles.css`, ни в `tw-animate-css`, ни в собранном CSS. Контент вкладок появляется рывком.
- **Палитра раздвоена:** тёплые коричневатые поверхности (hue 60) поверх холодного сине-серого фона (hue 255).
- **Нет семантических цветов.** Успех, предупреждение, VIP и «онлайн» заданы прямыми классами Tailwind: `emerald-400`, `amber-200/300/400`, `text-[oklch(0.83_0.13_68)]`, `rgba(251,191,36,.16)` — 25 вхождений в 8 файлах.
- **VIP оформлен тремя способами:**
  - золотое имя (`profile-display.tsx:61`);
  - янтарный бейдж `VipBadge` (`profile-display.tsx:68-79`);
  - «✦ VIP» со свечением в админке (`AdminPanel.tsx:330`).
- **Типографика без шкалы:** 17 разных размеров текста, включая произвольные 8, 9, 10, 11, 13, 14, 15 и 22 px; `text-[11px]` — 36 раз, `text-[10px]` — 19 раз. Подписи разделов набраны капслоком 10–11 px с разрядкой («ПОДЗАДАЧИ · 3», «ДОСТУП», «ПРОЕКТЫ · 4») — это читается как админка, а не как дорогой продукт.
- **11 уровней прозрачности текста** (`foreground/55…95`, `muted-foreground/65…75`) размывают иерархию. Варианты `muted-foreground/65–75` дают ≈3.1–3.7:1 на карточке: ниже WCAG AA (4.5:1) для мелкого текста.
- **Радиусы для одной роли разные:** карточки то `rounded-lg` (Обзор, Профиль, Сотрудники), то `rounded-xl` (Задачи, герой профиля, Настройки); поля и кнопки — `rounded-md`.
- **Глубины почти нет:** всё разделено бордерами 9% белого. Поповеры, меню и диалоги не отличаются от карточек. Оверлей диалога `bg-black/80` (`ui/dialog.tsx:24`) — тяжёлый.
- **Нативные `<select>` разной высоты** (h-7, h-8, h-9, h-10, py-1.5), нативные чекбоксы без стилей. Корню не задан `color-scheme: dark`, поэтому выпадающие списки и `datetime-local` в Windows/Chrome открываются светлыми системными окнами.
- **Обратная связь при нажатии непоследовательна:** `active:scale-[0.95/0.97/0.98]` расставлен вручную в отдельных местах; в базовом `Button` его нет.
- **Тосты** используют `richColors` sonner: собственные ярко-зелёные и красные цвета, не из палитры LUNO.
- **Английские остатки:**
  - 404 и экран ошибки (`__root.tsx:20-78`);
  - `sr-only "Close"` в диалоге;
  - «Level 3» и «L3» рядом с «Уровень 3» в админке;
  - заголовки матрицы прав `employee/manager/director`.
- **Разные слова для одного статуса:** фильтр «Не на связи» (`EmployeeDirectory.tsx:16`) и метка «Не в сети» (`profile-display.tsx:16`).

### 4.2 Шапка и навигация (`index.tsx:514-591`)
- Два маркера активной вкладки одновременно: серая «таблетка» `bg-secondary/70` и оранжевая полоска 2 px с `transition-all` (`index.tsx:537-555`). Визуальный шум, а `transition-all` анимирует и `left`, и `width` через layout.
- Логотип 34 px с графитовым «LUNO» плохо читается (см. 3.2).
- «Админ» стилизован не как вкладка и стоит вне `nav`. **[код] Ошибка состояния:** при открытой админке клик по вкладке меняет `active`, но AdminPanel остаётся на экране (`index.tsx:582-588`: остальные вкладки проверяют `!adminOpen`). Подсветка при этом показывает другую вкладку. Закрыть админку можно только повторным кликом по «Админ».
- «+ Заявка» — символ «+» в тексте вместо иконки.
- На узких экранах 7 вкладок уходят в `overflow-x-auto` без подсказки, что список прокручивается. Шапка фиксирована по высоте (h-16), а кнопки справа соседствуют с прокручиваемой навигацией.
- Подвал «© LUNO DIGITAL · Рабочее пространство команды» почти не несёт смысла. Его можно оставить, но сделать тише.

### 4.3 Обзор (`index.tsx:808-1012`)
- Заголовок «Обзор / Задачи проектов, доступных вам» — без приветствия и даты, не задаёт настроение главного экрана.
- 4 KPI-карточки одинакового веса. Подпись 12 px над значением, пояснение 11 px. Точка «live» повторена в каждой карточке и ещё раз в индикаторе LIVE.
- **Несогласованная семантика статусов:** в `statusClass` (`index.tsx:149-158`) «Новая» выделена оранжевым, а «В работе» серым. Во вкладке «Задачи» наоборот: оранжевый — «в работе».
- Клик по строке «Последние задачи» открывает вкладку «Задачи», но не саму задачу (UX-пробел; решение — раздел 10).
- Загрузка — текст «Загрузка задач…» рядом со скелетонами KPI.

### 4.4 Задачи (`TaskWorkspace.tsx`)
Самый проработанный экран: три колонки на xl с липкими колонками, рейл проектов, строки с иконками статуса, направляющие линии подзадач, сетка свойств, крупный таймер, Motion-пресеты. Остаточные проблемы:
- микроподписи капслоком 10–11 px и 8 степеней прозрачности текста;
- форма «Новый проект» разворачивается прямо в заголовке страницы, с полями `w-20`/`w-48` (`TaskWorkspace.tsx:762-773`). На узком экране ломает шапку;
- композер задачи: нативные `select` и `datetime-local` высотой 28 px;
- у комментариев квадрат с инициалами `rounded-md` вместо `ProfileAvatar` (`:1376`): фото автора не показываются, хотя везде они есть;
- кнопка подтверждения в AlertDialog белая (`bg-foreground`, `:415`) — третий стиль основной кнопки;
- ползунок ручного прогресса с бегунком 12 px (`:1178`) — маленькая область нажатия;
- история со своим скроллом `max-h-80` внутри липкой колонки — двойной скролл;
- колонка деталей — 6 секций подряд через разделители: длинная лента без группировки.

### 4.5 Сотрудники (`EmployeeDirectory.tsx`)
- Боковой список `sticky top-24` без ограничения высоты: при длинном списке «липкость» не помогает.

## 7. Риски редизайна
1. **Синхронизация с Lovable.** Ветка запушена; переписывать опубликованную историю нельзя (`AGENTS.md`). Нужны небольшие коммиты по этапам, без `--force`.
2. **`vite.config.ts`** изменён локально и не должен попасть ни в один коммит. Файлы добавляются только поимённо.
3. **Глобальная смена токенов** меняет все экраны сразу, включая неиспользуемые shadcn-компоненты. После этапа A нужен осмотр каждого экрана.
4. **`index.tsx` — монолит:** auth gate и четыре экрана в одном файле. Правки ограничиваются разметкой и классами; блок эффектов `194-417` не трогается.
5. **Инварианты мемоизации в `TaskWorkspace`.** Новые пропсы, обёртки или объекты в пропсах строк могут незаметно сломать оптимизацию (P1–P6).
6. **Замена нативных `select` на Radix Select** рискует регрессиями: недавний фикс `7ac71b2` касался ширины селекта исполнителя. Рекомендация — стилизовать нативные элементы.
7. **Разметка диалогов:** затемнение фона завязано на `role="dialog"` и `data-state`, поэтому остаются Radix-диалоги.
8. **Включение `animate-fade-in`** сразу «оживит» 8 мест. Нужно проверить, что нет мерцания при Suspense-фоллбэках и сдвигов вёрстки.
9. **Логотип:** оригинальную графику менять нельзя. Без светлой версии логотипа проблема контраста останется.
10. **Шрифты:** системный стек выглядит по-разному на macOS и Windows. Свой шрифт — это новый ассет, только по согласованию.
11. **Базовый уровень lint:** 2398 проблем до редизайна. `prettier --write` запускать нельзя — это гигантский дифф и конфликты с Lovable. Контроль только по приросту в изменённых файлах.
12. **Тестовая среда = продакшен-данные** (см. раздел 13): любые проверки с созданием или изменением данных пишут в боевую базу.
13. **Устаревшая документация:** `AGENTS.md` утверждает, что центр уведомлений работает на локальных демо-данных, но код использует реальный `get_my_notifications`. Без согласования не правится.

## 8. Дизайн-система Premium Apple для LUNO DIGITAL

**Принцип:** тёмная графитовая сцена, свет только в тексте и в одном оранжевом акценте; глубина — через тон поверхности, а не через свечение; движение плавное, физичное и заметное — интерфейс ощущается живым, но никогда не задерживает работу.

**Название продукта не меняется.** Во всех экранах, заголовках вкладок браузера, мета-тегах, сносках и текстах остаётся **LUNO DIGITAL**. «Premium Apple» — только название визуального направления, оно нигде не появляется в интерфейсе. Внутренние идентификаторы `nexa-*` в коде (ключи кэша, каналы, CSS-классы) остаются как есть.

**Тема.** Тема остаётся **только тёмной**, переключения тем сейчас нет, и удалять нечего. Токены строятся так, чтобы светлую тему на основе `#F5F5F7` можно было добавить отдельным этапом, если вы решите.

### 8.1 Цвет

Нейтральные цвета переводятся с тёплых коричневатых (hue 60) на нейтрально-холодный графит из брифа (hue ≈ 286, хрома ≤ 0.01). Светлота почти та же, поэтому плотность интерфейса не меняется. Палитра совпадает по тону с холодной базой фонового canvas, и раскол «тёплые карточки на холодном фоне» исчезает. Имена токенов shadcn сохраняются, поэтому классы в компонентах менять массово не нужно.

**Правила использования:**
- **Оранжевый** — только:
  - одна основная кнопка на область;
  - маркер выбранного (полоска 2 px, индикатор вкладки);
  - live-индикатор;
  - фокус.
  
  Им никогда не заливаются карточки, а статистика им не раскрашивается.
- **Статусы задач** — одна схема на всех экранах:
  - «Новая» — пустой серый круг;
  - «В работе» — оранжевый;
  - «В ожидании» — `--warning`;
  - «Завершена» — приглушённая галочка.
  
  Обзор приводится к схеме Задач.
- **Приоритеты** — текст и маленький глиф без заливки:
  - низкий — третичный;
  - средний — обычный;
  - высокий — `--warning`;
  - критический — `--destructive`.
- **Присутствие:** онлайн — точка `--success`, офлайн — полая серая точка.
- **Навигация:** активная вкладка получает **один** маркер. Рекомендация — графитовая «таблетка» с оранжевой точкой или полоской, через `layoutId`.
- **Наведение и нажатие:**
  - наведение — фон `--popover` или белый 4%;
  - нажатие — `scale(0.97)`, 120 мс;
  - неактивное состояние — прозрачность 40% и `cursor: not-allowed`.
- **Прозрачность текста** вида `text-foreground/70` запрещается. Используются только три текстовых токена: основной, вторичный, третичный.

- **Уровни глубины:**
  - 0 — холст и фон;
  - 1 — карточка: `--card`, бордер 7–8%, без тени;

- **Стекло — только в двух местах:**
  - липкая шапка при прокрутке: `background/72%` + `blur(20px) saturate(140%)`, как сейчас по `data-scrolled`;
  - оверлей диалога: `black/55`, без анимации blur.
  
  Карточки стеклом не делаются.
- **Радиусы** (концентрические):
  - контролы (поле, кнопка, сегмент) — 10 px;
  - элемент списка внутри карточки — 10 px;
  - карточка и панель — 16 px;
  - диалог — 20 px;
  - чип и бейдж — полные.
  
  Вводятся токены `--radius-control`, `--radius-card` и `--radius-overlay`.
- **Отступы** — сетка 4 px:
  - поля страницы 24 px (мобильные 16 px);
  - внутренние отступы карточки 20–24 px;
  - между секциями 32 px.
  
  Компактный режим продолжает работать через `--spacing`.
- **Области нажатия:** минимум 36 px на десктопе, 44 px на мобильном (ползунок прогресса, переключатели, кнопки «⋯»).

- **Button:**
  - варианты primary (оранжевая, тёмный текст), secondary, ghost, outline, destructive;

- **Dialog / AlertDialog:**

  - «Закрыть» по-русски;
  - одна основная кнопка оранжевая, белой больше нет.
- **Тосты:** стиль sonner на токенах (`--popover`, иконки `--success` / `--destructive`) вместо `richColors`.
- **Состояния:**

## 9. Движение: красиво, плавно, физично

**Цель:** анимации — одна из главных черт нового LUNO DIGITAL. Они должны быть **заметными, мягкими и «физичными»**: пружины вместо линейных переходов, элементы, которые перетекают из одного состояния в другое, ощущение веса и упругости. При этом каждое движение быстро завершается и не мешает работать. Сейчас этого не хватает: смена вкладок вообще не анимирована (неопределённый `animate-fade-in`), а индикатор навигации едет через `transition-all`.

**Инструменты.** Уже установленный `motion` (пружины, `layoutId` для общих элементов, `AnimatePresence`, `useSpring` для чисел) плюс CSS-переходы для простого. Новые библиотеки не нужны.

### 9.1 Фирменные анимации LUNO DIGITAL

| Где | Как это выглядит | Техника |
| --- | --- | --- |
| **Индикатор навигации** | Оранжевая «жидкая» капсула перетекает к новой вкладке: в полёте слегка вытягивается по ширине, у цели упруго дотягивается и успокаивается. Наведение — мягкий графитовый подсвет, нажатие — лёгкое «вдавливание» вкладки | `layoutId` + пружина (≈ stiffness 380, damping 30); растяжение через `scaleX` по скорости |
| **Смена вкладки** | Старый экран тает за 120 мс; новый поднимается на 8 px из лёгкой прозрачности, его блоки (заголовок → карточки → списки) появляются каскадом по 30 мс | `AnimatePresence mode="popLayout"` + `opacity`/`translateY`; каскад до 6 групп |
| **Вход в систему** | Хореография при открытии: свечение фона разгорается, логотип проявляется, затем поднимаются заголовок, поля и кнопка (каскад 60 мс, всего ≈ 600 мс). Нажатие «Войти» — кнопка мягко сжимается, текст сменяется спиннером без скачка ширины. Ошибка — поле подсвечивается и плавно раскрывается сообщение | Motion `staggerChildren`, пружина для кнопки; один раз за загрузку |
| **Успешный вход** | Форма уходит вверх и растворяется, заставка «LUNO DIGITAL» плавно перетекает в рабочее пространство вместо резкого «Проверяем сессию…» | `AnimatePresence` между экранами входа, заставки и приложения |
| **Выбор задачи / сотрудника / статьи** | Подсветка выбранной строки перетекает к новой строке (уже есть в Задачах — распространить на Сотрудников, Базу знаний и Уведомления); панель деталей сменяется сдвигом с растворением | `layoutId` + `SOFT_SPRING` (существующий пресет) |
| **Сегментированные фильтры** | «Таблетка» выбранного фильтра перекатывается по пружине (как «Все / Мои задачи» сейчас) — во всех фильтрах приложения | один компонент с `layoutId` |
| **Диалоги и меню** | Диалог выплывает из лёгкого уменьшения (0.96 → 1) по пружине, фон за ним мягко темнеет; меню раскрываются от точки вызова | Radix + Motion/`tw-animate-css`, `transform-origin` от триггера |
| **KPI на Обзоре** | Числа «досчитывают» до нового значения за ≈ 600 мс вместо мгновенной смены; изменение коротко подсвечивается оранжевым | `useSpring` / `animate` для чисел, `tabular-nums` против дрожания |
| **Нагрузка команды, прогресс** | Полосы плавно растут по пружине при первом показе и при изменении | `scaleX` от левого края |
| **Таймер** | Запуск — цифры «оживают»: короткий оранжевый перелив и мягкий пульс live-точки; пауза — плавное затухание акцента. Сами секунды не дёргаются | переход цвета 300 мс; тикает только `LiveSpent` |
| **Раскрытие форм** | Композер задачи, редактирование, отчёт, ответ — раскрываются плавно по высоте с растворением содержимого (как сейчас, но мягче и единообразно) | существующий паттерн `height: auto` + `EASE_OUT` |
| **Новые данные** | Новая задача, комментарий или уведомление «вплывает» на место, остальные строки плавно раздвигаются | `layout` у списка + появление `opacity`/`y` |
| **Наведение и нажатие** | Кнопки и строки: мягкий подъём фона при наведении (150 мс), упругое нажатие `scale(0.97)` с возвратом пружиной; карточки при наведении чуть светлеют по бордеру | CSS-переходы; пружина у основных кнопок |
| **Переключатели** | Бегунок переезжает по пружине с лёгким «перелётом», трек плавно наливается оранжевым | Motion-пружина (как сейчас, мягче) |
| **Тосты** | Выезжают из-за края с пружиной, складываются стопкой, уходят растворением | настройки sonner |

### 9.2 Параметры
- **Пружины** — основной язык движения:
  - мягкая (выбор, индикаторы, фильтры): stiffness ≈ 380–420, damping ≈ 30–38;
  - упругая (нажатия, переключатели): stiffness ≈ 500, damping ≈ 28 — с небольшим перелётом.
- **Длительности для не-пружинных переходов:**
  - микро — 150 мс: наведение, цвет;
  - стандарт — 240–280 мс: раскрытие, смена вкладки;
  - сцена — до 600 мс суммарно: хореография входа, «досчёт» KPI.
- **Кривые:**
  - появление — `cubic-bezier(0.22, 1, 0.36, 1)` (существующий `EASE_OUT`);
  - исчезновение — короче появления, 120–160 мс.
- **Прерываемость.** Любая анимация может быть прервана новым действием и плавно перенаправлена: быстрый клик по вкладкам не выстраивает очередь, пружина просто меняет цель.

### 9.3 Плавность без потери скорости
- Анимируются только `transform` и `opacity` — на GPU, 60 fps. Исключение — высота небольших раскрывающихся форм.
- Каскады только при первом показе и не длиннее 6–8 элементов; при realtime-обновлениях существующие строки не «пляшут».
- Не анимируются: сетка колонок Задач, длинные списки целиком, таблица матрицы прав.
- `will-change` — только на время анимации.
- Движение не блокирует ввод: клик, набор текста и фокус доступны сразу, формы не сбрасываются, лишних запросов нет, таймеры не сбиваются.
- Инварианты производительности Задач (`memo`, компараторы, `LiveSpent`) сохраняются: анимации добавляются внутри существующих компонентов, без новых пропсов у строк.

### 9.4 Доступность движения
- `MotionConfig reducedMotion="user"` переносится на уровень приложения (сейчас только в Задачах и аватаре).
- При `prefers-reduced-motion` пружины и сдвиги заменяются мягким растворением; при «Анимации: выкл» в Настройках всё мгновенно — как сейчас (`data-motion="off"`, `MotionGlobalConfig.skipAnimations`).

### 9.5 Чего не делаем
- новых постоянных движений фона и параллакса;
- длинных заставок и анимаций, которые нужно ждать;
- «тряски» полей при ошибке;
- анимации каждой ячейки в таблицах.
